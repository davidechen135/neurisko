# Kiroween 2026 官方规则 (Official Rules)

> 赛事官方地址：[https://kiroween.devpost.com/](https://kiroween.devpost.com/)  
> 主办方：Kiro (kiro.dev)

---

## 1. 赛事日程 (Timeline)

* **开始时间**：2026 年 10 月 30 日（提交通道正式开启，允许开始开发）
* **截止时间**：2026 年 12 月 4 日 14:00 PT（太平洋时间）/ 17:00 ET
* **项目有效性限制**：**仅限新项目（New Projects Only）**。只有在提交通道开启期间（2026年10月30日 - 12月4日）创建并构建的项目才符合资格，不可提交已有的旧项目。

---

## 2. 参赛资格 (Eligibility)

* **年龄与地区**：达到居住国法定成年年龄，面向全球开发者（常规受制裁国家/地区除外）。
* **参赛形式**：支持**单人参赛**或**团队参赛**。
* **账号要求**：参赛者必须在 [kiro.dev](https://kiro.dev) 注册并拥有有效的 **Kiro User ID**（或 AWS 账户 ID）以完成报名。

---

## 3. 赛题与赛道类别 (Theme Categories)

参赛作品必须选择并归属于以下四个万圣节主题类别之一：

### 1. Resurrection（死者苏生）
* **定义**：Bring your favorite dead technology back to life.
* **要求**：通过当今的技术创新重新构想过时、被淘汰的技术或软件，用于解决面向未来的新问题。

### 2. Frankenstein（技术缝合怪）
* **定义**：Stitch together a chimera of technologies into one app.
* **要求**：将看似互不相容、意想不到的多种技术元素强行拼装结合，打造一个出人意料且功能强大的全新应用。

### 3. Skeleton Crew（通用代码骨架）
* **定义**：Build a skeleton code template lean enough to be clear but flexible enough to support various use cases.
* **要求**：构建一个精简清晰但足够灵活的通用代码模板/脚手架；并且**必须基于该基础模板衍生展示两个截然不同的应用示例**以证明其通用性。

### 4. Costume Contest（装扮大赛 / 极致界面）
* **定义**：Build any app but show us a haunting user interface that’s polished and unforgettable.
* **要求**：构建任意可用应用，但必须呈现令人惊艳、极具氛围感且深度融合应用功能的精美 UI/UX 体验。

---

## 4. 提交要求 (Submission Requirements)

每个参赛项目在 Devpost 上提交时必须包含以下材料：

1. **可用软件应用（Working Software Application）**：
   * 必须在实际构建中深度使用 Kiro 的核心能力（如 Vibe Coding Chat、Agent Hooks、Steering Docs、MCP 或 Spec-driven 规范驱动开发）。
2. **公开源码仓库（Public Code Repository）**：
   * 需提供公开的 GitHub（或同等代码托管平台）链接，包含开源许可协议。
   * 仓库中需包含 `.kiro` 目录结构及配置（包含 Spec 文件、Steering 引导文档或 Agent Hook 脚本）。
3. **演示视频（Demo Video）**：
   * 时长约 3 分钟以内，公开发布在 YouTube、Vimeo 等视频平台。
   * 视频必须演示：完整的端到端运行流程、解决了什么问题，以及在开发过程中是如何使用 Kiro 的。
4. **Devpost 项目描述文档（Written Description）**：
   * 阐述项目灵感、产品功能、解决的问题、技术挑战以及 Kiro 在其中的具体应用细节。

## 5. 评审标准 (Judging Criteria)

评委将从以下五个维度进行独立评审与打分：

| 评审维度 | 衡量指标 |
| :--- | :--- |
| **Potential Impact（潜在影响力）** | 项目是否切实针对真实受众解决了一个真实问题？演示的方案是否有效？实用性、易用性与可访问性如何？是否真的会有人使用？ |
| **Technological Implementation（技术实现与 Kiro 深度）** | 是否充分且熟练地使用了 Kiro 的多项工具特性？AI 开发流程是否有深思熟虑的策略？是否展现出对 Kiro 功能的深度理解与创新实验？ |
| **Design（设计与体验）** | 项目是否提供了完整且协调的产品体验（而不仅是一个粗糙的技术概念验证 POC）？交互与界面设计是否直观、考究？ |
| **Innovation/Idea（创新与独创性）** | 概念是否富有创意和新颖性，是否区别于市面现有方案？是否以独特方式整合了冷门技术或公共资源/数据集？ |
| **Presentation（演示与表达）** | 视频是否清晰完整地展示了端到端工作流程？Pitch 是否讲清了问题是什么、面向谁以及为什么重要？整体表达是否清晰且引人入胜？ |
